# Performance: bound the working set and find the heat

Measure the existing path before choosing a technique. Separate query/count/aggregation time, per-row enrichment, response transfer, DOM insertion/layout/paint, controller initialization and work performed for unopened panels. Repeated source/PDF/tax lookups outside the visible page can dominate a small grid. Browser node count, markup bytes and long tasks matter alongside database time.

Render a bounded initial page/window with real rows and initialized essential actions. The right size depends on row complexity, user task and device; 50/100 in an example is a profile, not a universal requirement. Let the backend own filters, ordering, membership and full-set aggregates. Keep expensive summaries off the critical path when the user can work without them, and show their pending state.

Use deterministic sort tie breakers. Pagination should preserve selected identity and the active query. LIMIT/OFFSET can be adequate for bounded ranges but grows costly on deep pages; keyset/cursor designs can improve traversal when supported sorting/filtering and stable keys permit it. Virtualization bounds the mounted DOM for continuous scrolling; it does not fix an expensive query, eliminate backend payload, or automatically preserve keyboard/selection/accessibility. Choose and verify these options against actual needs rather than copying them into every host.

Select page identities before expensive enrichment when doing so preserves canonical membership/order. Profile query plans and indexes for actual predicates and sort keys. Change a query only with equivalence/regression evidence appropriate to its domain. Caching requires actor/tenant/filter/revision scope and invalidation; never share private data or serve stale finality simply to hit a target.

Delay optional panel datasets until intent. Coordinate supporting reads with bounded concurrency and deduplication; one serialized queue may suit a contended server, while another host benefits from measured limited parallelism. Avoid stampedes on selection/filter changes. Release language/runtime session locks after authorization when the framework supports it and there is no later need to mutate that locked session.

Reducing markup can help after other costs are understood. Prefer eliminating redundant hidden content and repeated data safely. Compression/compaction must preserve identifiers, attributes, text, accessibility and monetary values. A regular expression over arbitrary HTML is not a safe universal minifier. An uncertain fragment should remain intact or use the framework's supported serializer. Compare normal/raw output and preserve fallback/debug access. Smaller bytes alone do not establish a causal latency improvement.

Record first usable table/actions and supporting completion separately. A skeleton, HTTP200 or TTFB is not the user's working outcome. Retain failed budgets. Distinguish warm/cold, local/network-throttled and single/concurrent observations. Do not claim million-row capability, p95 or a universal sub-three-second SLA from a small local sample. The [verification guide](verification.md) defines an honest acceptance record.
