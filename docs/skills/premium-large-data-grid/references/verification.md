# Verification and evidence

Choose checks from the changed behavior and host risk. This skill's helpers exercise only synthetic local artifacts; they never release a user's hold on application suites. Direct full-test authorization requires the host's full maintained coverage; quoted examples do not supply it.

Define first usable: required real rows rendered, stable identities, controls/actions initialized and scope visible. Time from the declared user-trigger/navigation boundary to that condition. Define auxiliary completion independently and verify displayed facts actually painted. Record query time, payload bytes, row/DOM counts and browser long tasks when available. Choose representative datasets and budgets before measuring; a host may use 10k/100k or larger synthetic and real authorized populations, but record actual counts and grain.

Capture command, exit, complete result/log, timestamp, source/build fingerprints, runtime/device/viewport, cache/network condition and sample size. Keep first/later page, filters and separate small/large contexts; repeat enough to assess consistency. A p95 needs an appropriate declared distribution/sample, not a label on three observations. Synthetic delayed/failure runs test recovery and stay out of normal latency samples.

Observe the user journey, not only a selector: filter/sort, page, select/clear, open/close detail, contextual action, canonical receipt/state, reload/revisit, empty results and recovery where applicable. Business writes need existing authorization, isolated fixtures/rollback where appropriate and the owner's idempotency/finality conditions. UI readiness or a success banner is not completed business effect.

Test stale/foreign response rejection, mutation invalidation, missing/partial data, auth/refusal, timeout, duplicate request/retry and retained rows after auxiliary failure. Verify selected/full totals stay distinct and a same-count mutation is not presented as proof of unchanged data. Browser identity never authorizes an agent; compare its bounded snapshot with the actual active view and enforce server scope.

Inspect desktop geometry and mobile labels/touch controls, complete amounts, focus/menu dismissal, high text scale, long values and meaningful detail access. No page overflow alone does not prove readable digits. Keyboard/mouse/coarse-pointer, browser emulation, native Android and screen-reader verification are separate observations. Report what ran and what did not.

When a check fails, preserve the result and distinguish product, harness, environment, coverage and business-pending causes using evidence. Repair conservatively and rerun affected checks/regressions against the final version. Do not lower thresholds, remove coverage or widen exceptions to obtain green. Stop unchanged external retries; keep independent useful work moving and report the exact boundary.

Use host QA/review skills when available and relevant, or equivalent recorded checks. First review clarity, apply authorized cleanup, then verify the post-cleanup version. After QA, critically compare the build to its promises. Later repairs invalidate affected proof. A clean area can retain evidence only with a dependency rationale. Final required docs/links must exist; held checks remain HELD, not PASS. Separate technical delivery, human acceptance and domain finality.
