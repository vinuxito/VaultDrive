# Skin / Multi-Theme System — 2026-04-12

## Context

Implemented a 6-skin theme system matching the quantixmexico.net landing page aesthetic.
All changes are purely frontend (CSS + React). No backend, DB, or API changes required.

The landing page aesthetic: deep navy `#0a0a1a` background, neon cyan `#01fff7` + magenta
`#ea12ff` accents, glassmorphism cards, gradient scrollbar, ambient glow orbs.

---

## Architecture

### Approach: `data-theme` attribute + CSS custom properties

- `[data-theme="X"]` selector on `<html>` overrides all shadcn/ui CSS variables
- Dark skins also add `.dark` to `<html>` so Tailwind `dark:` utilities work
- ThemeProvider wires localStorage ↔ DOM attribute
- FOUC prevented by inline `<script>` in `index.html` that runs before React mounts

### Why not Tailwind config?

Tailwind v4 uses a CSS-based config (no `tailwind.config.js`). Our shadcn/ui components
already use `hsl(var(--primary))` etc., so overriding CSS variables per `[data-theme]`
automatically rethemes every component with zero component-level changes.

## FOUC Prevention

Without this, the first render would have no `data-theme`, so CSS variables would be undefined
(the old `:root {}` block was removed and moved to `[data-theme="X"]`), causing a flash of
unstyled/white content.

**Fix:** Added synchronous `<script>` in `index.html` `<body>` before `#root`:

```html
<script>
  (function () {
    var VALID = ["quantix", "light", "dark", "cyberpunk", "elegant", "business"];
    var DARK  = ["quantix", "dark", "cyberpunk", "elegant"];
    var skin  = localStorage.getItem("quantixdrive-skin");
    if (!skin || VALID.indexOf(skin) < 0) {
      var legacy = localStorage.getItem("vaultdrive-ui-theme");
      skin = legacy === "dark" ? "dark" : legacy === "light" ? "light" : "quantix";
    }
    document.documentElement.setAttribute("data-theme", skin);
    if (DARK.indexOf(skin) >= 0) document.documentElement.classList.add("dark");
  })();
</script>
```

This runs before React hydration, setting `data-theme` and `.dark` correctly on every load.

## Legacy Migration

| Old key | Old values | Maps to |
|---------|-----------|---------|
| `vaultdrive-ui-theme` | `"light"` | → `"light"` skin |
| `vaultdrive-ui-theme` | `"dark"` | → `"dark"` skin |
| (missing) | — | → `"quantix"` (default) |
| `quantixdrive-skin` | any valid skin | used directly |

Migration is handled in both the ThemeProvider `useState` initializer AND the inline HTML script,
so it works before and after React mounts.

## Risks & Open Items

1. **Service restart required.** The Go binary was rebuilt (`go build`) but `quantixdrive.service`
   was started before the rebuild. Run `sudo systemctl restart quantixdrive` to deploy.

2. **QuantiX skin orbs are static.** The landing page has slowly animating orbs. Our orbs use
   `background-image: radial-gradient` with `background-attachment: fixed` — static but visually
   identical at rest. Animating these would require CSS `@property` (Houdini) for smooth
   transition of gradient positions, which lacks full browser support. Defer.

3. **No "use system default" option in picker.** Dropped `system` from the Skin type.
   On first load with no stored preference, the inline script and ThemeProvider both default
   to `"quantix"`. A "System" 7th option could be added later that calls
   `resolveSystemSkin()` and stores the resolved skin.

4. **`luxury-tokens.css` and `elegant-complete.css` dark overrides still apply.**
   These files have `.dark { ... }` overrides for `--glass-bg` etc. Since dark skins add
   `.dark` to `<html>`, those overrides are still active and may partially override
   skins.css values. In practice this is fine — those token files only set supplemental
   luxury variables, not the shadcn core vars. No conflicts observed in testing.
