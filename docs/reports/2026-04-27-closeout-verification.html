Bugs / Risks

🔴 HIGH — Register accepts arbitrary-length passwords

Reproducible against the freshly-deployed binary. POST /api/register with a 5-character password ("short") returns 200 and creates the account. Source: handle_user_create.go, no length / complexity validation before auth.HashPassword.

🟡 MEDIUM — Register returns 500 on {} body instead of 400

Same handler. Empty fields proceed to bcrypt / DB insert and bubble up as a 500. Should validate Email != "" and Password != "" immediately after JSON decode.

🟢 LOW / NOTE — Encrypted-private-key KDF is single-round SHA-256

Source comment already flags Argon2id / PBKDF2 as the proper target. Migration with backward-compat needed.
