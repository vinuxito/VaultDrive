What changed to make verification reliable

Login now clears stale vault state

vaultdrive_client/src/pages/login.tsx now clears in-memory vault state after successful auth and before storing the new session. This closes a real stale-key/stale-credential safety gap.

Folder share modal now falls back from a bad cached PIN

vaultdrive_client/src/components/vault/CreateFolderShareLinkModal.tsx now drops back to manual PIN entry with a clear recovery message when an auto-used cached PIN cannot decrypt the private key.

Upload storage is configurable

The backend now uses UPLOAD_DIR when present. This made local and CI-style verification independent from repo-local filesystem ownership quirks.

Playwright now uses an isolated local database by default

playwright.config.ts now defaults to vaultdrive_playwright, creates the database if needed, runs goose migrations, and writes uploads to /tmp/quantix-playwright-uploads.

Failures found before the fixes

Initial harness startup failure FIXED

The managed Go server initially died with missing DB_URL / JWT_SECRET. That meant npm run test:e2e was not honest as a default local command.

Upload permission failures FIXED

Earlier E2E runs showed repeated permission denied errors while writing to repo-local uploads/. Those failures disappeared after routing the harness through a dedicated writable upload directory.

Shared dev database migration drift FIXED

The earlier local vaultdrive DB was missing governance migration 044, which broke settings/governance flows. The harness now migrates a dedicated Playwright DB cleanly.

Two failing unit tests FIXED

Both failing tests turned out to be real implementation drift, not test problems.

  • login.test.tsx: stale vault state was not cleared on a new successful login
  • CreateFolderShareLinkModal.test.tsx: cached PIN failure did not recover into manual PIN entry
