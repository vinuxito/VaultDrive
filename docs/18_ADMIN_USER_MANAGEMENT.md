# 18. Admin User Management

> Session: March 23, 2026
> Status: Build green, 14/14 E2E passing, Go tests passing

## Context

The Admin module had backend handlers (`handle_admin.go`) and a frontend page (`admin.tsx`) already built, but **the admin API routes were never registered in `main.go`**. The entire Admin section silently returned 404s. Additionally, key user management features were missing.

## What Was Done

### Phase 1: Wire Up Existing Admin Routes (critical blocker)

Registered 4 existing handlers in `main.go` that were previously dead code:

| Method | Path | Handler | Middleware |
|--------|------|---------|------------|
| `GET` | `/api/admin/users` | `getAllUsersHandler` | auth + requireAdmin |
| `PUT` | `/api/admin/users/{id}` | `updateUserAsAdminHandler` | auth + requireAdmin |
| `POST` | `/api/admin/users/{id}/reset-password` | `resetUserPasswordHandler` | auth + requireAdmin |
| `DELETE` | `/api/admin/users/{id}` | `deleteUserAsAdminHandler` | auth + requireAdmin |

### Phase 2: Create User from Admin Panel

- **Backend**: New `createUserAsAdminHandler` in `handle_admin.go`
  - Reuses `generateRSAKeys()` and `encryptPrivateKey()` from `handle_user_create.go`
  - Accepts: first_name, last_name, username, email, password
  - Validates all fields + password minimum 6 chars
  - Generates RSA keypair, encrypts private key, creates user
- **Frontend**: "New User" button + modal with all 5 fields + error display
- **Route**: `POST /api/admin/users`

### Phase 3: PIN Reset from Admin Panel

- **Backend**: New `resetUserPINHandler` in `handle_admin.go`
  - Clears: pin_hash, pin_set_at, pin_failed_attempts, pin_locked_until, private_key_pin_encrypted
  - User will need to re-enroll their PIN on next login
- **SQL**: New `ResetUserPINAsAdmin` query in `sql/queries/users.sql`
- **Frontend**: Lock icon button per user row + confirmation dialog
- **Route**: `POST /api/admin/users/{id}/reset-pin`

### Phase 4: Admin Role Toggle

- **Backend**: New `toggleAdminHandler` in `handle_admin.go`
  - Prevents removing admin from own account
  - Accepts `{ is_admin: bool }` body
- **SQL**: New `SetUserAdminStatus` query in `sql/queries/users.sql`
- **Frontend**: Clickable role badge (Admin/User) with confirmation dialog
- **Route**: `PUT /api/admin/users/{id}/admin-status`

### Phase 5: Bulk Delete

- **Backend**: New `bulkDeleteUsersHandler` in `handle_admin.go`
  - Accepts `{ user_ids: [...] }` body
  - Skips self-deletion and invalid UUIDs
  - Returns `{ deleted: N, skipped: N }` counts
- **Frontend**: Checkbox column, select-all header checkbox, floating red action bar
  - Own account row has no checkbox (cannot self-delete)
  - Selected rows highlight with red tint
  - "Clear selection" link to deselect all
- **Route**: `POST /api/admin/users/bulk-delete`

### Phase 6: v.cazares@abrn.mx Admin Promotion

- New migration: `sql/schema/035_add_vcazares_admin.sql`
- Applied directly via psql (goose not installed on server)
- Verified: both `filemon@abrn.mx` and `v.cazares@abrn.mx` now have `is_admin = TRUE`

## Admin API Reference

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/api/admin/users` | List all users |
| `POST` | `/api/admin/users` | Create new user |
| `PUT` | `/api/admin/users/{id}` | Update user details |
| `POST` | `/api/admin/users/{id}/reset-password` | Reset user password |
| `POST` | `/api/admin/users/{id}/reset-pin` | Clear user PIN |
| `PUT` | `/api/admin/users/{id}/admin-status` | Toggle admin role |
| `DELETE` | `/api/admin/users/{id}` | Delete single user |
| `POST` | `/api/admin/users/bulk-delete` | Delete multiple users |

All admin endpoints require: JWT auth + `is_admin = TRUE`.

## Security Notes

- All admin endpoints protected by `requireAdmin` middleware (403 if not admin)
- Self-deletion prevented in both single and bulk delete
- Self-demotion prevented in admin toggle
- Password hashed with bcrypt before storage
- RSA keypair generated for admin-created users (same as self-registration)
- PIN reset clears all PIN-related fields including `private_key_pin_encrypted`
- No audit logging on admin actions yet (future improvement)
